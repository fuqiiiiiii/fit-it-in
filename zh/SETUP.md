# Daily Planner · 设置（第一次使用）

和 `AGENTS.md` 一起读；§5 这类编号指的是那个文件。

目标：让用户回答得越少越好。**能推断的先推断，推断不出来的才问。**

1. **检查环境。** 当前会话必须以这个仓库为工作文件夹，并且能用 Google 日历连接器。缺日历连接器 → 明确告诉用户要连哪个连接器，然后停下。仓库不是工作文件夹 → 告诉用户从自己的仓库开一个会话，然后停下：之后建的定时任务，只有在已经连着仓库的会话里创建，才读得到这个文件夹。
2. **先读再问。** 列出用户的所有日历和未来 7 天的事件。推断：时区；哪些日历看起来是固定日程（课程、工作、共享的）；哪个是他自己的主日历；哪些重复习惯像锚点；他的邮箱。
3. **先说你看到了什么，再只问一个必答问题**：
   ```
   我看了一下你的日历：
   · 时区：<时区>
   · 固定日程（我只读不写）：<日历>
   · 工作块和 ddl 我会写进：<主日历>
     （想单独用一个日历？在 Google 日历里新建一个叫「Planner」的日历，告诉我就行。）

   只需要你回答一个问题：每天早上几点把当天安排发给你？
   ```
4. **一个可跳过的问题**：「可以跳过：你一般几点吃午饭、晚饭？平时要通勤吗？」跳过 → 这些字段留空，绝不替他编作息。
5. **预览。** 用他真实的日历画一份今天的 brief（§5），问「这样对吗？」。他纠正的地方写进配置：能放进结构化字段的就放进去，放不进的在**补充规则**里写一行。
6. **写配置。** 把 `config/profile.example.md` 复制成 `config/profile.md`，`config/settings.example.md` 复制成 `config/settings.md`，填好值，commit `config: initial setup`，push。push 失败就停下，照实说。
7. **在这个会话里创建每天的定时任务**：
   - 名字 `Daily Planner brief`；在云端运行，不需要电脑开着
   - 时间：`CRON_TZ=<他的时区> <分> <时> * * *`，用他选的时间，这样夏令时会自动处理。如果调度器调整了分钟，告诉他确切的时间
   - 提示词（原样复制，填上语言）：
     > Daily Planner 早上运行。读这个仓库里的 AGENTS.md，按**早上的 brief** 模式（§5）执行。之后用户可能直接在这个会话里回复，按 §6–§9 处理。语言：<语言>。
   - 推送通知打开，邮件通知关闭（brief 自己会发邮件）
   - 说清这个任务拿到的是哪种批准设置。如果运行时需要人工批准，告诉他可以在任务设置里改成自动批准
8. **收尾。** 发一条消息：第一份 brief 什么时候、在哪里收到，再给三句他可以直接说的话（「实验报告周五交」「essay 做完了」「brief 改到 8 点」）。然后回到他最初想做的事（如果有的话）。

设置时绝不问容量上限、时长系数、最小空隙这些参数。用默认值，以后他想改用大白话说就行。
